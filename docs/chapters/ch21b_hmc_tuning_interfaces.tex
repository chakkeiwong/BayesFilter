\chapter{HMC Tuning Interfaces}
\label{ch:bf-hmc-tuning-interfaces}

Hamiltonian dynamics execute a kernel only after its mass matrix, step size,
and trajectory length have been fixed.  Choosing those quantities is a
different operation from drawing transitions with them.  BayesFilter makes
that boundary explicit because a chain runner that happens to adapt a step
size can otherwise be mistaken for a complete tuning procedure.

\section{Terms and authority}

A \emph{tuner} is a public, repository-owned orchestration route.  It may issue
a canonical tuning artifact only after its required stages and fresh
verification pass.  A \emph{chain runner} executes one supplied configuration;
it does not become a tuner when it dual-averages only the step size.  A
\emph{stage helper} implements an internal or diagnostic part of the ladder,
and direct use of it does not inherit public artifact authority.

A \emph{tuning artifact} records scope-bound evidence for a selected fixed
kernel.  Its draws are tuning draws, not retained posterior draws.  A
\emph{final handoff} consists of a replayable private kernel payload and a
redacted public status record.  It exists only when the route's tested
admission rule passes.

\emph{Ordinary coordinates} are the target adapter's coordinates.  The
ordinary tuner builds affine mass coordinates around them.  \emph{Fixed-
transport coordinates} are the latent coordinates (z) of one frozen,
identity-bound nonlinear map.  Replacing that map changes the tuning scope.
\emph{Neural-force mechanics} means a fixed position-only force combined with
an exact endpoint potential.  That description alone supplies neither a
nonlinear transport nor mass or leapfrog-count tuning.

When sources disagree, the checked mathematical target and project policy come
first, followed by executable signatures and behavioral tests, then the
validated capability registry and its generated documentation.  Historical
plans and result notes do not override current executable behavior.  The
registry classifies authority and supported behavior; an evidence anchor in
the registry identifies the test that checks each behavioral statement.

\section{Ordinary-coordinate tuning}

The public import is
\code{from bayesfilter.inference import HMCKernelTuningConfig,
tune\_hmc\_kernel}.  With the default runner, the adapter must bind its
dimension, stable signature, target scope, exact log value, matching score,
and value--score capability.  This configuration selects the one reviewed
ordinary policy.  It does not let a model caller insert candidate grids, mass
windows, tuning draw counts, a runner binding, a bare chain callback, or
private handoff mechanics.

The ordinary route performs the following linked stages:

\begin{enumerate}
  \item initialize geometry and a positive-definite mass representation;
  \item run a bootstrap screen for a viable fixed-(L) step;
  \item by default, update mass in bounded windows and requalify the step after
    every coordinate change;
  \item evaluate the complete primary grid
    \(L\in\{3,5,9,13,18,25\}\), tuning epsilon independently for every
    value from the same frozen metric and checked four-chain start bank;
  \item evaluate one refinement barrier containing every untested floor and
    ceiling integer midpoint adjacent to a surviving primary value, again with
    an independent epsilon tune for every \(L\);
  \item order eligible measured pairs deterministically for verification,
    without treating that order as a statistical ranking; and
  \item freeze the kernel and run fresh verification on draws not used for
    candidate selection.
\end{enumerate}

The geometry-derived trajectory target helps order viable candidates.  It does
not construct the primary grid, eliminate a primary value before measurement,
or trigger a second local \(L\) search after the broad barriers.

Fresh verification consumes the eligible measured pairs directly and starts
at most two candidates from the deterministic queue in one attempt.  A passing
candidate ends tuning.  Otherwise, a consistent acceptance-direction signal
may seed another complete attempt, but it cannot bypass mass adaptation or
either broad-grid barrier; conflicting signals do not mutate epsilon.  The
public configuration fixes
\path{operational_verification_bracket_policy} at
\path{single_repair}.  The old \path{one_verified_log_midpoint} procedure
is accepted only by the explicitly selected historical shared-epsilon helper
route and is not an ordinary public-tuner option.

Each candidate binds the mass-artifact signature, target scope, coordinates, and
metric signature.  A mass-signature change invalidates the selection and its
calibration: the stage emits a hard veto and no final handoff, and fresh tuning
is required under the new geometry.

For the ordinary configuration, the resolved public variant is
\path{ordinary_hmc} with algorithm identifier
\path{ordinary_broad_fixed_metric_selection_v1}.  The public config
fixes the upper bound at \(L=25\) so that it cannot silently truncate the
primary grid, and it exposes neither a caller-selected grid nor the private
P4-E covariance-multiplier switch.  The former shared-epsilon
\path{operational_paired_fixed_trajectory_selection_v3} identity and the
internal \path{joint_l_epsilon_grid_fixed_mass_hmc} identity remain
readable compatibility records; the public artifact-authority boundary rejects
both.  The route
payload separates \path{operational_authority}, replayable
\path{artifact_authority}, and \path{scientific_promotion_authority}.
Operational or replayable authority does not establish a scientific claim.
The current ordinary result is explicitly non-admitting for claim-bearing use
while its known NumPy runtime-policy debt and XLA-default mismatch remain
unresolved.

The package exports one implementation entry for each public tuner.  The
ordinary export delegates to
\path{bayesfilter.inference.hmc_tuning_dispatch.tune_hmc_kernel}; the ordinary
implementation module contains only the private canonical executor.  The
fixed-transport package export delegates to the sole implementation in
\path{bayesfilter.inference.fixed_transport_hmc_tuning_tf}.  Chain runners,
stage helpers, and compatibility procedures do not define additional public
tuners.

Geometry is a shared responsibility rather than an unspecified tuner default.
The caller supplies the initial center and may supply a local geometry
hypothesis; the tuner validates that hypothesis and owns the subsequent affine
construction and adaptation.  Under windowed adaptation, it tries a supplied
negative log-posterior Hessian, an initial covariance, and positive diagonal
parameter scales, in that order, before falling back to identity.  Thus a
negative Hessian means

\begin{equation}
  H(\theta_0)=-\nabla_{\theta}^{2}\ell(\theta_0),
  \qquad
  \Sigma_0 \approx H(\theta_0)^{-1},
  \label{eq:bf-ordinary-hmc-initial-geometry}
\end{equation}

\noindent
in the same unconstrained coordinates as the supplied center.  With geometry
fallback enabled, a rejected higher-priority hypothesis is recorded before the
next is tried; with fallback disabled, it is a hard error.  The explicit fixed-
identity policy ignores all hints.  Identity is a useful mechanics baseline,
not evidence that an anisotropic posterior has identity geometry.

A covariance-first calculation must keep the estimated center and covariance
together.  The covariance should be finite, symmetric, positive definite,
estimated at the supplied center, and expressed in the adapter's coordinates.
Exact target and score replay must pass there, and any regularization or
fallback remains part of the provenance.  The following listing checks this
argument binding with stubs and therefore performs neither covariance fitting
nor HMC.

configuration currently defaults to \code{use\_xla=False}, which is a mismatch
with the repository XLA-default policy rather than an implicit qualification.

reviewed exception.  The typed proposal-field branch's exposed tuning
hyperparameters have no numeric constructor defaults, but the implementation
still fixes four chains and \code{float64}.  A candidate supplies an explicit
raw-position bank \(q_i\), \(i=1,\ldots,4\).  With initial diagonal factor
\(A=\operatorname{diag}(s)\), the tuner uses
\begin{equation}
  c=\frac{1}{4}\sum_{i=1}^{4}q_i,
  \qquad z_i=(q_i-c)A^{-\mathsf T},
  \qquad q_i=c+z_iA^{\mathsf T}.
  \label{eq:bf-tensorflow-hmc-initial-bank}
\end{equation}

deliberately replicated and recorded; a candidate may not use that compatibility
path.  The remaining fixed policies are \(L=1\) in metric windows, a powers-of-
two trajectory grid, and a stateless seed-offset scheme.  The implementation
also inherits TensorFlow Probability's internal dual-averaging defaults except
for the explicit adaptation count and target acceptance.  These are interface
policies rather than evidence of posterior convergence or default readiness.

\section{A frozen nonlinear transport}

Let the base log density in model coordinates be
\(\ell_{\theta}(\theta)\), and let one frozen differentiable bijection map
latent coordinates into those model coordinates,
\[
  \theta = T(z), \qquad J_T(z)=\frac{\partial T(z)}{\partial z}.
\]
The fixed-transport HMC target is
\begin{equation}
  \ell_z(z)
  = \ell_{\theta}\!\left(T(z)\right)
    + \log\left|\det J_T(z)\right|,
  \label{eq:bf-fixed-transport-hmc-target}
\end{equation}
and its matching score is
\begin{equation}
  \nabla_z\ell_z(z)
  = J_T(z)^{\mathsf T}\nabla_{\theta}
      \ell_{\theta}\!\left(T(z)\right)
    + \nabla_z\log\left|\det J_T(z)\right|.
  \label{eq:bf-fixed-transport-hmc-score}
\end{equation}
Dropping either Jacobian term changes the target or its derivative.  Such a
calculation is wrong relative to the transformed-target claim.

The public tuner constructs the transformed adapter itself, hashes the
transport manifest, and uses a fixed identity mass in (z).  It tunes step
size and chooses a leapfrog count from its declared policy, then performs fresh
candidate or held-out verification.  It does not perform ordinary windowed
mass adaptation.  A supplied chain runner is scoped only after the transformed
adapter has been built; this argument is not a generic arbitrary-force hook.
Changing the transport manifest, base or transformed adapter signature, target
scope, dimension, backend, or coordinate identity invalidates reuse.
Its ESS and verifier policies are selected by the fixed-transport
configuration.  The ordinary route's disabled tuning-ESS status and 1.01
\(\widehat R\) threshold do not transfer automatically.

\subsection{Joint fixed-transport tuning}
\label{sec:bf-fixed-transport-joint-tuning}

The artifact-authoritative fixed-transport tuning policy is
\texttt{measured\_joint\_grid\_v1}.  It treats the step size
\(\epsilon\) and the leapfrog count \(L\) as a coupled design choice.  A
configuration therefore supplies a finite, explicit set
\(E\) of positive step sizes and at least two distinct values of \(L\).  The
runner measures every pair in \(E\times\mathcal L\) with the same frozen
transport, target, coordinate identity, chain bank, and fixed-kernel screen.
The configured maximum candidate count is checked before execution.  No
result at an unmeasured neighboring step is inferred from a result that was
measured.
The dataclass does not silently construct a grid; the no-configuration
convenience call supplies a small repository baseline and records it as a
convenience hypothesis rather than target-specific evidence.

For a transition started from \(x\), write
\begin{equation}
  a(\epsilon,L\mid x)
  =\mathbb E\!\left[\min\{1,\exp(-\Delta H)
      \}\mid x\right]
\end{equation}
for the expected Metropolis probability, and let
\(b(\epsilon,L\mid x)\) denote the probability of a Bernoulli accept/reject
decision.  The implementation reports the sample mean of the former and the
sample mean of the latter separately.  Neither quantity is a convergence
diagnostic.  Candidate selection also records movement, squared jump distance,
energy/error telemetry, divergence availability, and target/score finiteness;
their roles are explicit in the tuning artifact.

The distinction is necessary because fixed-length leapfrog dynamics do not
make \(a(\epsilon,L)\) monotone in \(\epsilon\).  For the unit harmonic
oscillator, the leapfrog phase is
\begin{equation}
  \vartheta(\epsilon)=\arccos(1-\epsilon^2/2),
  \qquad 0<\epsilon<2,
\end{equation}
and a trajectory has phase \(L\vartheta(\epsilon)\).  Values near a return
phase can have high acceptance and little net movement.  Consequently, a
factor-of-two increase after a high-acceptance screen (or decrease after a
low-acceptance screen) is a proposal for another experiment, not evidence
about that experiment.  The former ladder is retained only as
\path{legacy_directional_diagnostic_v1}; its records are stamped
\path{diagnostic_only_legacy_policy} and cannot be handed to a retained
sampler.

Under the measured policy, replicated fixed-kernel efficiency evidence is
collected for every candidate that survives the basic validity screen, then a
disjoint held-out fixed-kernel run qualifies the nominated pair.  Missing or
non-finite acceptance and missing retained movement are hard failures.  An
acceptance value outside the target band is recorded as a repair diagnostic,
but is not a measured-route validity veto: a target such as 0.70 is an
efficiency heuristic, not a correctness condition.  The payload labels a
healthy candidate \texttt{mechanics\_validated}, an efficiency-eligible row
\texttt{tuning\_candidate}, and leaves \texttt{posterior\_ready} false until a
separate retained-chain assessment.  Thus acceptance cannot by itself
establish convergence, correctness, mode discovery, or sampler superiority.

The July 2026 LGSSM validation caller is retained as historical compatibility
code and explicitly uses \path{legacy_directional_diagnostic_v1}.  Its
one-$L$ ladder can emit diagnostic records but cannot issue an
artifact-authoritative handoff.  An active caller must provide a reviewed,
target-specific measured grid before it can issue a claim-bearing result.

The same explicit legacy classification applies to the historical
fixed-transport benchmark callers in this checkout: the weighted three-mode,
paper-d100, German reverse-comparator, strong-smooth, defensive analytic,
banana-repair, replication, q=20 CPU validation, q=20 global-mixing, q=20
seed-B, and Chart-A six-$L$ scripts.  Their configurations select
\path{FIXED_TRANSPORT_HMC_LEGACY_DIAGNOSTIC_POLICY} and the historical
\path{acceptance_target_distance} selector, so a bare
\texttt{passed} value cannot issue a current measured-grid handoff.  A caller
that is intended to be active must replace that explicit legacy policy with a
reviewed finite \path{step_size_candidates} grid and at least two
\path{leapfrog_grid} values before it can use the measured policy.

\section{Typed deterministic proposal-field mechanics}

\code{run\_full\_chain\_neural\_force\_hmc} consumes a supplied mass
coordinate system, fixed (L), and fixed or dual-averaged epsilon.  Directly
calling it with (M=I), (L=1), and a few adaptation transitions establishes
only that this configuration ran.  It does not establish mass adaptation,
trajectory selection, fresh verification, or a reason to reject HMC or the
target.

For a raw-coordinate frozen force, the public binding factory requires and
identity-binds a coordinate-consistent endpoint potential and issues an
\texttt{HMC\allowbreak Tuning\allowbreak Runner\allowbreak Binding}.  The
binding is accepted by the public facade only together with
\texttt{TensorFlow\allowbreak HMC\allowbreak Kernel\allowbreak Tuning\allowbreak Config};
\texttt{HMC\allowbreak Kernel\allowbreak Tuning\allowbreak Config} rejects it
and continues to use the exact adapter score.  The typed TensorFlow branch owns
its affine mass wrapper, epsilon,
(L), screening, verification, and repair.  This branch is not the canonical
ordinary broad-grid policy, and its result remains mechanics-only.  The binding
must report finite values, divergence and energy status, movement, endpoint
target health, deterministic execution identity, and source closure.  It
rejects the low-level runner's direct identity-coordinate fallback.  A bare
Python callable is rejected by the public ordinary tuner.
The binding proves the declared software identity and coordinate semantics; it
cannot prove that the supplied endpoint function equals the claimed target.
That equality still requires a target-specific value check.

The typed objects use potential, not log-density, signs.  If
\(\ell(\theta)=\log \pi(\theta)\), the exact endpoint object is
\begin{equation}
  U(\theta)=-\ell(\theta).
  \label{eq:bf-neural-force-endpoint-potential}
\end{equation}
For the scalar-potential-gradient semantic, the proposal force is
\(F(\theta)=\nabla U(\theta)=-\nabla\ell(\theta)\).  The kick uses
\begin{equation}
  p_{n+1/2}=p_n-\frac{\epsilon}{2}F(q_n),
  \qquad
  q_{n+1}=q_n+\epsilon M^{-1}p_{n+1/2},
  \label{eq:bf-neural-force-kick}
\end{equation}
followed by the symmetric terminal kick and momentum flip.

The v2 binding also permits an honestly labeled deterministic position-only
proposal field \(B(q)\) that need not equal \(\nabla U(q)\).  Position-only
kicks remain volume-preserving shears, and the symmetric schedule remains
reversible.  The exact endpoint Metropolis rule is
\begin{equation}
  \alpha
  = \min\left\{1,
      \exp\bigl[-U(q')-K(p')+U(q)+K(p)\bigr]\right\}.
  \label{eq:bf-neural-force-endpoint-correction}
\end{equation}
Under these conditions, the endpoint potential determines the invariant target;
a poor or sign-reversed proposal field can destroy efficiency without by itself
changing that target.  A wrong endpoint potential, missing coordinate change,
momentum-dependent field, asymmetric schedule, or direct state update invalidates
that conclusion.

For an affine mass coordinate \(\theta=c+Fz\), the repository wrapper applies
the chain rule to the proposal field and endpoint potential.  The affine
log-Jacobian is constant and is deliberately omitted from energy differences
under the declared \code{constant\_omitted} convention.  Both raw objects and
that convention are bound into runner schema
\path{bayesfilter.hmc_tuning_runner_binding.v2}.

\section{Artifacts, failures, and conclusions}

Before consuming a tuning result, a caller checks that the public route has
artifact authority, the result and capability schema versions are supported,
the target and coordinate scope match, all bound identities and source closure
are present, fresh verification passed, and the private replay payload is
available at the BayesFilter-owned boundary.  Tuning draws must be discarded.

A passing typed TensorFlow candidate is consumed with
\path{build_retained_bound_hmc_archive_runner_from_tuning_result}.  The builder
requires the same repository-issued runner binding and durable tuning manifest,
and it rejects a diagnostic or failed result.  It reuses the frozen endpoint
target, deterministic proposal field, affine geometry, step size, leapfrog
count, and final state rather than switching to an ordinary exact-gradient
kernel.  A retained extension names the immediately preceding archive as its
continuation manifest; BayesFilter verifies that predecessor and resumes from
its final active-coordinate state.  This typed archive path is a
frozen-mechanics handoff, not posterior admission; its binding's
\code{artifact\_authority=False} cannot be upgraded by a consumer.

An in-memory ordinary result retains private initial and adapted mass arrays;
its redacted public status does not.  Before process exit,
\path{admitted_kernel_mechanics_payload_from_tuning_result}
converts a passed result into the durable JSON-ready replay form.  It reuses the
validated geometry already carried by the result, so nonidentity initialization
does not require the consumer to rediscover hidden hints.  The payload binds the
target, scope, execution settings, initial position, adapter identities, and
both mass signatures.  The corresponding mechanics-payload replay helper
checks those fields and reconstructs the fixed adapter without invoking tuning
or HMC.  In contrast, reconstruction from an older serialized tuning payload
requires the original explicit geometry inputs and private array-bearing data.

with an empty \path{claim_bearing_blockers} collection.  It must also set
\texttt{claim\_bearing\_artifact\_\allowbreak authority=True}.  Before
reconstruction it
recomputes the ordinary epsilon/L policy from the repository-owned

policy and blocker list.  A caller-edited authority flag or blocker list
therefore cannot grant authority.  The boundary also checks the persisted
replay role, so a mechanics-only payload cannot acquire claim authority through
a caller-supplied flag.  The current ordinary route fails this gate while its
known NumPy runtime-policy blocker remains.  The
durable ordinary helper consequently emits the explicit
\path{mechanics_only} role,
\texttt{authority\_status=\allowbreak mechanics\_only\_\allowbreak nonclaiming},
and the source
\path{tuning_config}; this describes reusable transition
mechanics and does not admit posterior or scientific claims.
