sequence requires further guard admission, high-precision recursion diagnosis
and joint-KL/model-adequacy calibration before the remaining experiments. Its
source-reference phase requires only a small example, while its full empirical
phase follows the TensorFlow port. Its checkpoint is regenerated by code that
reinstates the same repair-first sequence. Finally, a completed experiment

author runtime: the 4,000-estimate Figure 4 matrix was a TensorFlow GPU run.

The remedy is to retain one authoritative master, archive its previous
revision, separate full source replication from port replication, and put
enhancements after both. Preserve all evidence and its implementation identity.
Do not reinterpret a diagnostic PASS as filter admission or source replication.

| Audit risk | Required correction |
|---|---|
| Wrong baseline | Pin author commit, data, driver, runtime, dtype, RNG and solver conventions separately for every selected experiment. Octave execution cannot establish MATLAB identity. |

| Uninformative commands | Status and checkpoint checks answer planning consistency only. New full-source drivers and phase specifications must exist before advertising those phases as executable. |
| Scope drift through improvements | New projection, clipping, damping, floors, bandwidth/loss changes and optimizer searches cannot be used to close source-faithfulness gaps. Source-prescribed protections remain part of the source algorithm. |
| Budget mismatch | Preserve live CPU and GPU balances and the exhausted attempt tranche. Forecast original-source costs separately; a TensorFlow GPU estimate is not a source-runtime estimate. Do not silently convert GPU hours into a new CPU allowance. |

The revised design passes this pre-edit audit provided these corrections remain
