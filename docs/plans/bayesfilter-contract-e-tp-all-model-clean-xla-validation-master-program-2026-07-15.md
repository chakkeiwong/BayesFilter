## Outcome Sought

Apply and validate the clean functional-loop engineering scheme across every
scientifically eligible Contract E--TP model family without transferring LGSSM
features, charts, dimensions, targets, or tolerances by convenience. For each
row, establish whether the same finite TensorFlow value and total-score program
can execute with bounded XLA graph topology on the trusted GPU at the row's
declared horizon, or classify the row as a scientific negative result or a
target/adapter blocker before expensive compilation.

This program validates engineering topology and the executed finite scalar. It
does not authorize Contract E--TP as canonical, default, leaderboard, or
HMC-facing. Contract E--Chol remains the only canonical reset.

## Binding Design Rules

1. Every compiled row uses TensorFlow/TFP only. NumPy/SciPy are restricted to
   offline preparation, reference, and reporting roles.
2. Dynamic time, lookahead, RK4, quadrature-block, reverse, and iterative-solver
   recursions use `tf.while_loop`, `tf.scan`, or a proved equivalent functional
   loop. Python horizon loops and Python tensor-history lists are ineligible.
3. A shape-changing initial step and no-reset terminal step may be statically
   dispatched. The fixed-shape intermediate recurrence must be one functional
   body.
4. Parameter-dimension Python loops are not automatically forbidden when fixed
   and tiny, but the compiled graph audit must show they are not the horizon-
   scaling cause. New code should prefer batch-native parameter tangents.
5. Reverse autodiff is tried only after graph construction is bounded. If XLA
   reverse mode fails, use model-owned explicit JVP/VJP or forward tangents; do
   not stop gradients or change the scalar.
6. Every invalid compiled chart must expose a Boolean invalid predicate and
   poison carried numerical state. XLA assertions alone are insufficient.
7. Each model owns its features, support, continuation horizon, chart, and
   preparation protocol. LGSSM lookahead 8 is a reference pattern, not a
   cross-model default.
8. `0.05*sqrt(p)` remains only the individual-direction same-scalar FD screen.
   It is never a cross-method, cross-dtype, or CPU/GPU equivalence margin.

## Quantitative Topology Gates

For each model, choose a short horizon that includes at least one intermediate
loop iteration and compare it with the target full horizon. Predeclare the exact
pair in the phase plan. Unless a reviewed model-specific constant-capture
argument justifies a stricter or looser byte bound:

- both traces contain the required functional loops;
- top-level-node and function-node full/short ratios are `<=1.10`;
- GraphDef-byte full/short ratio is `<=1.25`;
- no reachable clean-route helper contains Python time/window/solver unrolling;
- full-horizon compilation completes inside the row budget and is reported
  against the historical unrolled or short-rung baseline without inventing a
  universal seconds threshold.

These are topology gates, not scientific tolerances. If tensor shapes
legitimately grow with horizon, the phase must separate constant-body graph
nodes from captured constant bytes before execution rather than relaxing a
failed gate afterward.

## Phase Program

### Phase 0: Registry, Topology Inventory, And Default Audit

Freeze row targets, scientific eligibility, existing adapters, Python-unrolled
surfaces, shape changes, derivative owners, feature recursions, reference
routes, and current artifacts. Audit every inherited quadrature order,
lookahead, feature family, chart policy, dtype, threshold, and horizon for
provenance and status. Produce a row-by-row continuation/blocker ledger.

Gate: no eligible row has an unresolved target identity or silent convenience
default; negative and blocked rows are not scheduled for GPU work.

### Phase 1: Shared Clean-Loop Primitives And Static Guardrails

Extract reusable first/intermediate/terminal orchestration only where model
shapes permit it. Add AST/reachable-source guards for Python time/window/RK4/
solver loops and graph inventory utilities that count top-level and function-
library loops. Preserve model-specific flow and feature functions.

Gate: LGSSM clean-XLA regressions, compiled fail-closed control, and static
audits pass. Shared abstraction must not change the LGSSM scalar or graph gates.

### Phase 2: Early Structural Support Regression

Make the exact structural fixture loop-native and rerun support, completion-
residual, tangent, compiled fail-closed, and off-support negative controls before
any new model GPU campaign. This is the shared guard that functional-loop
refactoring has not weakened support semantics for singular dynamics.

Gate: the exact structural fixture passes locally and in the smallest trusted
compiled configuration. Failure is a shared continuation veto for later model
GPU work until repaired.

### Phase 3: Scalar-SV Loop-Native Feature And Filter Core

Build actual-SV and KSC-SV loop-native target-continuation features and scalar
filter recursions. Treat the two observation targets separately despite shared
state dimension. Start at `T=2,10,100`, verify against frozen unrolled/dense
references, then audit parameter-region chart stability before `T=1000`.

Gate: each row independently passes same-scalar, chart, topology, fail-closed,
and reference diagnostics. A failure in one row does not block the other unless
it identifies a shared-core defect.

### Phase 4: Scalar-SV Trusted Full-Horizon GPU/XLA

Run fresh-process trusted GPU/XLA short/full graph and compile ladders for
scientifically eligible scalar-SV rows. Record float64 first; a dtype-generic
float32/TF32 arm requires its own numerical audit and cannot be produced by an
outer cast over float64 constants.

Gate: the exact full-horizon compiled factory/configuration passes total-score
identity, declared same-scalar FD/tangent checks, happy-path execution, and its
own compiled fail-closed control; graph ratios pass, no fallback occurs, and
CPU/GPU drift does not change the prior scientific classification. Warmed
runtime regressions remain visible.

### Phase 5: Predator--Prey Loop-Native Core

Preserve real-plane support and the initial-observation-before-transition time
order. Convert target continuation and any RK4 substeps used in the compiled
route to functional TensorFlow loops. Validate `T=1,2,5` against semi-analytic
and corrected-time-order references before `T=20`.

Gate: same finite scalar/score parity, support/time-order identities, topology,
and fail-closed checks pass. Approximate `T=5` SGQF remains approximate.

### Phase 6: Predator--Prey Trusted GPU/XLA

Run short/full trusted GPU/XLA with graph, compile, warm, memory, and numerical
artifacts. Do not substitute the forbidden retained-grid Zhao--Cui route.

Gate: the exact `T=20` compiled factory/configuration passes total-score
identity, declared same-scalar FD/tangent checks, happy-path execution, and its
own fail-closed control, or a bounded blocker is written. No exact nonlinear
filtering or Zhao--Cui parity claim follows.

### Phase 7: SIR/DSGE Boundary Re-Audit

Re-audit whether SIR has obtained a mathematically complete target law and all
total derivative owners, and whether an executable DSGE/NAWM client has been
registered. Reuse Phase 2 as the mandatory support guard, but require each
admitted client to add its own model-specific structural identities and compiled
negative control. Do not implement a new probability law or client model
without an explicit owner decision.

Gate: SIR and DSGE/NAWM either enter through newly reviewed target contracts
with model-specific support tests or remain explicit blockers.

### Phase 8: Eligible Structural/High-Dimensional GPU/XLA

Execute only structural/high-dimensional rows admitted by Phase 7; predator--
prey remains governed by its separate Phase 6 result. Require innovation-space loops for
genuinely singular dynamics and batch-native tensor operations for high state
dimension. Preserve fixed-TTSIRT component/full-score boundaries.

Gate: the exact per-row full-horizon compiled factory/configuration passes clean-
XLA, total-score identity, declared same-scalar FD/tangent, model-specific
support, happy-path, and fail-closed evidence, or a bounded blocker is written.

### Phase 9: Cross-Model Regression And Compiler Red Team

Run shared regressions, compare graph ratios, compile/warm tradeoffs, memory,
fail-closed controls, and source audits across all eligible rows. Search for
hidden unrolled helpers reachable beneath clean factories, retracing per theta,
TensorList boundary escapes, dynamic-shape gradient operations, and CPU
fallbacks. Rehash all controlling artifacts.

Gate: no row is called clean XLA from a wrapper token alone; graph artifacts and
trusted runs must agree.

### Phase 10: Terminal Scientific And Engineering Synthesis

Produce all-model engineering, numerical, scientific, blocker, inference-
status, run-manifest, and post-run red-team tables. Separate candidate failure,
target invalidity, missing adapter, and infrastructure failure. State explicitly
which rows reached full horizon and which did not.

Gate: every frozen row is `pass`, `negative_result`, or `blocked` with an exact
artifact-backed classification and appropriately qualified numerical evidence.
“Program complete” must not be rewritten as “all models validated.”
