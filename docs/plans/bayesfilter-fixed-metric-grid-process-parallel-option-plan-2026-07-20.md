# BayesFilter Fixed-Metric Grid Process-Parallel Option Plan

Date: 2026-07-20

Status: `COMPLETE`

## Objective

Make process-parallel candidate execution an explicit opt-in execution mode
for the existing fixed-metric HMC `L`-grid search. Serial execution remains the
compatibility default. Candidate mathematics, seeds, tuning, screens,
extensions, failure typing, survivor admission, and refinement policy remain
unchanged.

## Evidence Contract

| Item | Contract |
| --- | --- |
| Question | Can the same fixed-metric grid semantics execute independent `L` candidates concurrently in spawned processes? |
| Baseline | Existing serial `run_fixed_metric_grid_search` result for identical configuration, lineage, policy, and deterministic callbacks |
| Candidate mechanism | `process_parallel` mode using a spawn pool and an application-owned importable runner factory |
| Pass criterion | Parallel and serial candidate payloads, survivor sets, seeds, and failure scope are identical after excluding declared execution-mode metadata |
| Vetoes | Fork use, missing explicit GPU/CPU environment policy, non-importable factory, worker crash treated as candidate rejection, changed seeds/budgets, or changed survivor semantics |
| Explanatory diagnostics | Worker count and execution mode |
| Nonclaims | No universal speedup, GPU capacity, convergence, mass adequacy, retained sampling, or scientific claim |

## Design

- Add public `run_fixed_metric_candidate` so applications never call the
  private `_run_candidate` helper.
- Add `FixedMetricGridExecutionConfig` with modes `serial` and
  `process_parallel`.
- Keep `serial` as the default and preserve existing callback arguments.
- In process mode, require an importable `module:factory` locator. The factory
  is imported inside each child after BayesFilter applies the declared worker
  environment, and returns the target-specific tune and screen callbacks.
- Require the worker environment to declare either CPU-only
  `CUDA_VISIBLE_DEVICES=-1` or `TF_FORCE_GPU_ALLOW_GROWTH=true`. Applications
  using GPU must still configure and verify TensorFlow memory growth before
  constructing targets or tensors.
- Use `multiprocessing.get_context("spawn")`; never use `fork`.
- Run Round 0 as one complete process barrier. If refinement is enabled, derive
  refinement values only after valid Round-0 completion and run them as a
  second process barrier.
- Candidate-local failures remain candidate records. Shared invalidity is a
  shared grid result. Target and resource vetoes propagate to the caller.
  Worker bootstrap, factory, serialization, or process failures become shared
  execution invalidity, never candidate rejection.

## Skeptical Audit

- **Wrong baseline:** rejected; exact serial semantic equality is the test
  oracle.
- **Proxy promotion:** rejected; timing is not a pass criterion.
- **Missing stop conditions:** process crashes and callback construction fail
  closed as shared invalidity; target/resource vetoes retain their scope.
- **Unfair comparison:** seeds and complete candidate requests are generated by
  the existing BayesFilter code in both modes.
- **Hidden assumptions:** spawn still imports the application main module;
  applications must keep TensorFlow target construction out of top-level main
  import and use the child factory.
- **Stale context:** this extends the current broad-grid API rather than the
  superseded local/directional tuner.
- **Environment mismatch:** process mode requires an explicit CPU-hidden or
  GPU-memory-growth environment declaration.
- **Artifact insufficiency:** result payload records execution mode and worker
  count while preserving existing private/public mechanics boundaries.

The audit passes because scheduling is isolated from numerical candidate
semantics and serial remains the reversible default.

## Required Checks

1. Existing serial tests remain unchanged and pass.
2. Public single-candidate execution matches the candidate inside serial grid
   execution.
3. Spawn-parallel and serial results match for Round 0 and refinement.
4. Reversed candidate order produces the same parallel result.
5. Candidate-local rejection remains local in parallel mode.
6. Worker factory/bootstrap failure becomes shared invalidity.
7. Target/resource veto scope is preserved.
8. Process mode rejects missing factory, `fork`, and ambiguous GPU memory
   policy.
9. MacroFinance switches from `_run_candidate` to the public function and its
   focused tests pass.

No GPU search or scientific experiment is authorized by this API phase.
