     Marginal weights for the M13 particle-flow likelihood and score
                while preserving LGSSM and KSC-SV
                                      BayesFilter technical note

                 4 October 2026; implementation status updated 6 October 2026


Implementation status, 6 October 2026. The marginal-mixture extension is implemented in
commit f5e69d716. It accumulates the affine matrix and its tangent in the shared flow loop, evaluates
both full Gaussian mixtures, and differentiates the finite recursion analytically. The original ancestor
policy remains the default. The current main algorithm chapter includes the complete recursion,
density and score derivations, and completed three-model evidence. This proposal preserves the original
derivation and prospective optional defensive component; that component has not been implemented.
References below to proposed experiments describe the October 4 plan. The October 5 experiments
are complete: LGSSM/KSC showed material non-inferiority conditional on the tested datasets, and
range–bearing showed lower errors than ancestor weights but still lost to bootstrap filtering on observed
likelihood error. The expanded October 6 campaign tests fresh data, longer horizons, dimensions and
cost; it does not itself run surrogate HMC.
    The proposed repair is to sum over possible ancestors in the importance correction, while retaining
the existing UKF covariance lifecycle, LEDH flow, Contract E reset, and analytical differentiation. This
is the marginal particle-filter construction applied to the actual affine flow proposals. It changes the
finite likelihood approximation and therefore needs a distinct route identity and its own tuning. It is
not the unchanged Li–Coates Algorithm 1.
    The purpose remains testing surrogate HMC. A particle-filter score may supply a force for proposals,
but the Metropolis calculation must use the declared endpoint target. A better filter score can make
those proposals more useful; it does not by itself establish posterior correctness or convergence.
    The mathematics below establishes the proposed one-step integration identity and the total derivative
of the resulting finite program. It also establishes why a universal finite-sample improvement claim
would be wrong. The existing LGSSM and KSC-SV computations are preserved by retaining their
existing route, then checking that preservation through the actual consumers. The new M13 route must
earn admission by measurement.

must check this induction. The implementation now follows this call chain. Fourteen full-filter FP64
finite-difference cases check both policies and every physical parameter direction in seven scopes at
batch size one; broader scope checks are ongoing.

6    Preserve the original LGSSM and KSC-SV values and scores
Preservation has a precise and achievable meaning. Existing qualified scopes keep their existing
algorithm, prepared observations, base designs, settings, coordinate transforms and consumer endpoints.
The proposed correction is an explicit optional mode selected before tracing. It must not be a parameter-
dependent switch and must not silently become the factory default. The mode is generic; this does not
justify a reduced, model-specific implementation of the canonical flow.
Proposition 3 (Preservation by unchanged execution). Let Aold (θ; ξ, c) denote the current finite
program with fixed inputs ξ and controls c. If the new factory’s legacy mode calls that same program on
those same inputs, with no changed operations, then on its valid differentiable domain

                   Alegacy (θ; ξ, c) = Aold (θ; ξ, c),       DAlegacy (θ; ξ, c) = DAold (θ; ξ, c).    (21)

Proof. The function computed in legacy mode is the same function. Equal differentiable functions on a
neighborhood have equal derivatives there. If the implementation returns a separate analytical score,
preserving its operations and inputs also preserves that returned score, including any pre-existing error.
This proposition does not newly certify that score.

7    Implementation and the smallest discriminating experiments
The M13 consumer runs through ledh_range_bearing_target_tf.py, ledh_canonical_batch_fused_
tf.py, and the shared executor ledh_canonical_score_tf.py. The optional policy importance_
weight_policy="marginal_mixture" calls marginal_prior_ratio_tangent in ledh_marginal_weights_
tf.py. The ancestor policy remains the default. Commit f5e69d716 contains this implementation and
its first completed three-model comparison.
     The shared flow returns the affine matrix and its tangent together with the auxiliary endpoint and
its tangent. The mixture routine evaluates both Gaussian mixtures at all children using log-sum-exp
and analytical responsibility reductions. Automatic differentiation and finite differences are independent
diagnostics only. At N = 4096 the exact chunk extent is K = 2048. There are N 2 component/child
pairs per step: tiling controls memory, not this arithmetic cost. No nearest-ancestor truncation is used.

Manual proofs above establish the stated conditional identities. MathDevMCP has verified the two-
