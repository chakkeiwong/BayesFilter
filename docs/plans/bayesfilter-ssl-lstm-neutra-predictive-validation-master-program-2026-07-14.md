## 5. Non-Negotiable Mathematical Contracts

### 5.1 Target Coordinate Contract

The base adapter consumes the exact A1 unconstrained free coordinate
`theta in R^4`. The prior transform/Jacobian convention is already part of that
target. NeuTra must not add, remove, or duplicate a constrained-parameter
Jacobian.

### 5.2 Transport Direction And Density

All public/internal names must use the declared direction:

```text
theta = forward_z_to_theta(z)
z = inverse_theta_to_z(theta)
```

The transformed density is:

```text
log_pi_z(z) = log_pi_theta(forward_z_to_theta(z))
              + log_abs_det_dtheta_dz(z)
```

The exact score is:

```text
score_z(z) = J_forward(z)^T score_theta(theta)
             + grad_z log_abs_det_dtheta_dz(z)
```

HMC must never use only the first term. Forward/inverse sign conventions must
not be inferred from generic names such as `transform` or `bijector`.

### 5.3 Reverse-KL Training Objective

For `z ~ N(0,I)`, minimize the Monte Carlo mean:

```text
-log_pi_theta(T(z)) - log_abs_det_dtheta_dz(z)
```

up to constants independent of transport parameters. Batch reduction is a
mean. Replicating rows or changing batch order must not change the per-example
objective or scale gradients unexpectedly.

### 5.4 Frozen-Transport Boundary

HMC may consume only an immutable frozen transport. A frozen artifact binds:

- target semantic and adapter signatures;
- parameter names and order;
- direction and logdet convention;
- transport family, topology, masks, activation, scale bounds, and component
  order;
- every tensor and its dtype/shape/hash;
- training configuration and seed lineage;
- runtime/backend policy and explicit nonclaims.

No optimizer or mutable `tf.Variable` may be reachable from the HMC binding.

  value_score_batch(theta) -> value[B], score[B,4]

## 9. Cross-Phase Repair Policy

For any material failure:

1. classify it as target, transport math, training, artifact, runtime/XLA,
   tuning, sampler, analytic-control, predictive-statistics, model, or resource;
2. decide whether it invalidates evidence or only rejects the current candidate;
3. run the smallest discriminating repair within a prospective phase plan;
4. preserve the failed artifact and seed;
5. rerun focused checks before any longer command;
6. stop after the declared repair/budget boundary rather than hunting seeds or
   relaxing criteria;
7. record what failed, what remains viable, and what evidence would overturn
   the conclusion.

One focused native review is required for mathematical/numerical logic changes,
public API changes, or material scientific conclusions. Repeated external
review is optional and not a substitute for executable evidence.

## 10. Runtime And Resource Policy

- TensorFlow/TFP is the implementation backend.
- Serious NeuTra training is trusted GPU/XLA work with `jit_compile=True`.
- Serious SSL-LSTM HMC is trusted GPU/XLA unless a reviewed phase explicitly
  establishes another route.
- External analytic-control or independent sample generation may use multicore
  CPU when appropriate, with GPU hidden deliberately and metadata recorded.
- Probe, compile, and mechanics runs must remain small and cannot support
  sampler/scientific claims.
- Every long run uses a prospective wall/GPU-hour cap, sequential stopping, and
  fresh non-overwriting artifacts.
- TensorFlow must not be initialized in a parent before spawning independent
  worker processes; use spawn-safe topology or isolate analytic-control
  computation.
- XLA evidence requires actual compiled execution. CPU tests, graph tracing, or
  a `jit_compile=True` flag without execution are insufficient.
- No `jit_compile=False` fallback may be silently promoted after an XLA failure.
