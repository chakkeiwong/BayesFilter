# P0 Subplan: Scope, Identity, Defaults, And Budget Freeze

Phase objective: turn the master program into an executable, machine-readable
campaign without launching learned training or serious HMC.

Entry conditions: Chapter 48 and its audit pass; NeuTra Tier A target/result
artifacts are readable; master program and runbook exist.

Required artifacts:

- program, target, assumption, command, and budget ledgers under the fresh root;
- exact Tier A target/chart/data/filter hashes and Tier B requalification rows;
- frozen P1/P2 APIs, training objective terms, architecture/LR/batch/step grids,
  tuning candidates, energy thresholds, seed domains, and command ceilings;
- source-transfer ledger for `~/python` historical HNN code, explicitly
  excluding the invalid delayed-acceptance behavior.

Required checks/reviews:

- replay the five Tier A evidence anchors and target identities;
- verify blocked NeuTra cells are excluded;
- inspect active target APIs and GPU/XLA/memory-growth policy;
- skeptical audit of baselines, proxy roles, budgets, default provenance,
  filtering boundary, and whether commands answer the question;
- one bounded Claude review of the master program and one focused review of P1
  if the master review raises a material implementation issue.

Evidence contract: P0 proves only that scope and commands are coherent and
reproducible. It does not admit a kernel, learner, sampler, or result.

Forbidden claims/actions: no training, serious HMC, package mutation, target
repair, historical pass promotion, or claim that a file name establishes
identity.

Exact P1 handoff: all ledgers validate; every Tier A row binds readable target
and chart evidence; P1 API and negative tests are frozen; budgets are within
the master ceiling; no material review issue remains.

Stop conditions: inconsistent target evidence, missing irreplaceable Tier A
identity, program budget conflict, or a material method choice requiring user
direction. A Tier B portability gap is recorded and does not block P1.

Phase-end duties: run local ledger/schema/path checks; write the P0 result;
refresh P1; review P1; continue if no real blocker.
