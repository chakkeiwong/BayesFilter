# Independent Review: Filter-Independent SIR Classifier-Ratio Plan

Reviewed plan: `bayesfilter-sir-classifier-ratio-score-plan-2026-08-13.md`  
Date: 2026-08-13  
Verdict: `REVISE_AND_EXECUTE`

## Review Question

Does the plan actually estimate

`[log p(theta+epsilon e_j, y_obs) - log p(theta-epsilon e_j, y_obs)]/(2 epsilon)`

using only observation paths generated by the simulator, with no filter,
latent-state posterior, or analytical complete-data score dependency?

## Findings

1. **Scientific target:** correct. Balanced class odds give the marginal
   observation density ratio, and the central difference is the declared score
   approximation. The plan does not substitute a Fisher expectation or a
   particle estimate.
2. **Data leakage:** addressed. Training, architecture selection, Platt
   calibration, and untouched testing are disjoint; the actual observed path is
   evaluated only after freezing each head.
3. **Classifier calibration:** addressed. Held-out log loss, Platt calibration,
   ECE, slope, and observed-path support are explicit gates. Accuracy is not a
   promotion criterion.
4. **Perturbation bias:** addressed. Four epsilon values and an epsilon-squared
   extrapolation are required; fewer than three admitted values veto a score.
5. **Exact-oracle coverage:** addressed. The exact simulator includes mean and
   log-scale coordinates, so passing cannot be explained by a purely linear
   classifier on a location-only problem.
6. **Filter contamination:** requires implementation enforcement. The SIR
   adapter must implement only the generative transition and observation maps;
   it must not import the analytical score teacher, filtering module, particle
   code, or the prior Fisher utility. Add AST and runtime module-deny tests.
7. **Full-path target:** correct. A summary statistic would define a different
   likelihood; the plan keeps every observation coordinate and time point.
8. **Statistical interpretation:** appropriately descriptive. Three classifier
   replicates are insufficient for superiority or algorithm ranking; the plan
   forbids those claims.

## Required Revisions Before Execution

- Keep the previous Fisher-importance artifacts only as historical off-target
  evidence; do not read them in the new runner.
- Add a source-level deny test for forbidden imports/calls and a runtime loaded
  module audit.
- Add a simulator parity test against the repository source simulator using the
  same fixed random-normal bank at `theta=0` for a tiny SIR horizon. This tests
  the new generative adapter without importing a score implementation.
- Add an exact Gaussian classifier-ratio test before SIR execution.

## Audit Verdict

After these revisions, the plan is executable. A passing SIR result will mean
only that the simulator-only ratio reference is admitted under its calibration
and extrapolation gates. It will not by itself certify a GenUT score or rank
algorithms.

Post-review compute amendment: full-batch (`4096` rows) XLA optimizer updates
replace `256`-row mini-batches. The loss, examples, splits, model classes, and
gates are unchanged. This is an execution-efficiency repair and removes
mini-batch noise; it does not change the classifier-ratio estimator. Verdict
remains `REVISE_AND_EXECUTE` after the required tests pass.

## Exact-Oracle Attempt 01 Repair Audit

The first full exact-oracle run failed every horizon/coordinate admission gate.
Failure was concentrated in the Gaussian log-scale coordinate: the reviewed
plan specified centered squared standardized features, but the implementation
used raw squares.  For a variance ratio this introduces an avoidable positive
offset proportional to path dimension before the tanh layers and produced the
observed near-chance scale classifiers.

Repair: change only the declared quadratic feature from `z**2` to `z**2 - 1`.
Because training standardization gives every training coordinate unit second
moment, this is the frozen centered-square feature.  Data, architecture sizes,
optimizer, regularization, epsilon ladder, splits, exact target, score identity,
and all gates remain unchanged.  Add a focused centering regression test and
use a fresh versioned output directory.  The failed attempt remains preserved.

Repair audit verdict: `REPAIR_PLAN_IMPLEMENTATION_MISMATCH_AND_RERUN_ORACLE`.
SIR remains a continuation veto unless the repaired full oracle passes.
