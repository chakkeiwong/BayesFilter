# State-space validation: pooled recovery and reference repair

The owner requested a reviewed plan and execution after the September 29 run
finished with three complete K4 fits, four K0 tuning timeouts, one funded slot
not started and 24 unfunded slots. This amendment authorizes a new continuation
window using the existing grant. It preserves the original campaign's deadlines,
receipts and failures as historical execution facts; it does not reset charges.

## Question and evidence contract

Can the public ordinary tuning pipeline complete the original state-space
workloads with bounded, progress-aware common-pool recovery, and can independent
assessment report stopped-interval agreement with checked numerical references?
The numerical baseline is the executed frozen source
`a8c6c6107c2da78d25a144be28a3503431352681465e338e945fca899f0a0e43`, under
`artifacts/hmc-shared-gpu-recovery-2026-09-29/prepared-r5/source`.

Engineering success requires actual dispatch into the existing checkpoint
continuation helper after an exhausted local cap; unchanged target/data/seeds
and completed numerical evidence; bounded process-group shutdown; one enclosing
charge; preservation of every original slot; and coverage calculations that
separate analytic truth, empirical integration sensitivity and unavailable
references. Tests must exercise the dispatcher, not just its scheduling helper.

Sampler checks retain the declared acceptance, finite-state/score/status,
movement and fresh-verification rules. All verified pairs remain retained;
R-hat is reporting-only in tuning. Posterior warmup, R-hat, precision and
reference checks remain separate. Runtime is a scheduling diagnostic, never a
scientific ranking criterion. Grid sensitivity is not a rigorous error bound.
No guarantee of convergence, calibrated coverage, superiority or all-model
success follows from completion. K6 retains its explicitly limited integration
and diagnostics role without an independent joint posterior oracle.

| Observation | Role and response |
| --- | --- |
| Exhausted attempt with durable numerical progress | Repair trigger: another bounded common-pool quantum, no reset of cumulative cost |
| Completed favorable or unfavorable assessment | Terminal result: preserve, never rerun to improve the outcome |
| Nonfinite accepted state, corrupt checkpoint/source, missing required provenance or unexpected coordinator failure | Continuation veto for affected work; diagnose before resuming |
| Diagnosed rejected invalid proposal during preparation | Existing checked preparation-restart mechanism may be evaluated in a new configuration |
| Posterior/reference failure | Promotion veto, preserved in reporting; other model work continues |
| Missing numerical reference or excessive grid sensitivity | Coverage unavailable/ambiguous, never a pass |
| Shared-pool, attempt or absolute deadline exhaustion | Stop the affected allocation and retain explicit incomplete dispositions |

## Skeptical review before implementation

Review verdict: proceed with the above corrections. A larger fixed timeout
alone would repeat the recovery integration defect. A whole-lane allocator
would still suppress nonlinear coverage. A new numerical source would invalidate
old checkpoint bindings, so runtime recovery uses the old source; reference
reporting is independently versioned. Grid estimates must not be inserted into
an exact-truth table. K5/K6 require full development validation, not promotion
from a short bootstrap. Existing unfavorable outcomes must remain counted.

The main unresolved assumption is affordability of K5/K6 and seed-dependent
search expansion. The six-hour stage measures that rather than hiding it with
an all-finished promise. For this infrastructure repair the comparison is the
actual failed queue and preserved numerical results, not a method-superiority
study: the cheap falsification controls are unchanged exact-Gaussian K0,
independent Kalman/score reference, and existing nonlinear reference/mechanics
checks. They veto incorrect plumbing and arithmetic; they do not tune settings.
If source, reference or numerical assumptions break, stop the affected lane.
If merely the current candidate fails, retain it and continue the explicitly
planned repair/independent work within the same budget.
