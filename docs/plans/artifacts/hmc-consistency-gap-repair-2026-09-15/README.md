# HMC consistency repair evidence

The plan and terminal audit are in the parent `docs/plans` directory. These
results are engineering checks on tiny exact Gaussian targets and synthetic
failure histories. They do not establish posterior convergence, a general
tuning success rate, or a ranking of kernels.

`validation-r8.xml` records the final broad regression gate.
`automatic-regressions-r2.xml` records the complete automatic isotropic and
anisotropic tests. Their run directories preserve manifests, candidate results,
preparation progress, checkpoints, and frozen execution specifications.

Large numerical trace inventories are committed as `numerical-traces.tar.gz`
inside each run's tuning directory. Every archive member was compared byte for
byte with the original JSON file; `numerical-trace-archives.json` records archive
hashes. To inspect or load a checkpoint from a fresh checkout, extract that
archive in its containing directory first:

```sh
tar -xzf numerical-traces.tar.gz
```

The live local originals remain unchanged and ignored. Immutable source checks
still apply: records from intermediate development sources are historical
debugging evidence and cannot be resumed as if generated by the final source.

`cpu-xla-r2` verifies XLA compilation and retained replay on intentionally hidden
GPUs. `gpu-readiness-r1.json` records why trusted GPU validation could not start.
The checked `xla_smoke.py` also supports a `gpu` argument when a permitted GPU
becomes idle; GPU launch still requires trusted access and memory growth.

The guide built successfully. `page414.png` and `page420.png` preserve inspected
pages, and `guide-render-inspection.json` identifies their source PDF. The three
unresolved citations in the build are pre-existing bibliography warnings.

Earlier failed logs are preserved. The terminal audit distinguishes reproduced
runtime defects, historical test migration, harness errors, and passing repairs.
